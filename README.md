# TI Feed

Сбор фида для последних 100 образцов MalwareBazaar с обогащением из
APT ETDA и VirusTotal. Результат: [output/feed.jsonl](output/feed.jsonl),
один JSON-объект на строку, ровно шесть полей из задания.

## Запуск

Python 3.10 или новее. Зависимости:

```bash
python -m pip install -r requirements.txt
```

Для загрузки из API используется существующий `.env` в корне проекта с переменными
`MALWAREBAZAAR_API_KEY` и `VIRUSTOTAL_API_KEY`.
Все команды выполняются из папки проекта.

Репозиторий включает исходный набор `cache/` и готовый фид `output/feed.jsonl`.
Для пересборки на сохранённых данных ключи и `.env` не нужны:

```bash
python main.py --mode build
```

| Команда | Действие |
| --- | --- |
| `python main.py` | Весь процесс: использовать кэш, загрузить недостающее, собрать фид |
| `python main.py --mode build` | Только сборка фида из кэша, без API и без ключей |
| `python main.py --mode sources` | Только MalwareBazaar и ETDA |
| `python main.py --mode vt` | Недостающие отчёты VT для сохранённых 100 хэшей |
| `python main.py --refresh` | Заново запросить все источники и собрать фид |
| `python main.py --mode vt --refresh` | Заново запросить отчёты VT для сохранённых хэшей |
| `python main.py --mode sources --refresh` | Загрузить свежую сотню MalwareBazaar и справочник ETDA |

После прерванного сбора VT достаточно повторить `python main.py --mode vt`,
затем выполнить `python main.py --mode build`.
Без `--refresh` сохраняется исходная сотня из кэша; новую сотню получают
обновлением источников. `build` требует оба исходных JSON и все 100 отчётов VT.
При недостающем или повреждённом отчёте сборка завершается с ошибкой,
предыдущий фид сохраняется. `--refresh` к режиму `build` не применяется.

## Совмещение данных

`md5` и `sha256` берутся из MalwareBazaar. SHA-256 связывает образец с файлом
отчёта VirusTotal; проверяются идентификатор отчёта и совпадение MD5, если
он присутствует в отчёте. Порядок образцов сохраняется.

`signature` сопоставляется с названием `value` и псевдонимами `meta.synonyms`
в ETDA. Используются нормализация Unicode NFKC, приведение регистра и
удаление пробелов и знаков пунктуации: например, `Gh0stRAT` совпадает с
`Gh0st RAT`. Поиск точный после нормализации; поиск по подстроке и похожему
написанию не используется.

Карточки объединяются только по идентичному UUID или явной связи `same-as`.
Связи `used-by`, `variant-of` и `related-to` не означают одно семейство.
Если имя подходит нескольким независимым группам, совпадение считается
неоднозначным и классы не назначаются.

`malware_family` содержит канонические названия сопоставленных карточек и
исходную сигнатуру, если её нормализованное имя отличается от канонических.
Все псевдонимы карточки автоматически в фид не добавляются.
При отсутствии карточки сохраняется исходная сигнатура; при `null` список пуст.

`malware_class` определяется по типам найденных карточек ETDA:

| Тип ETDA | Класс из задания |
| --- | --- |
| `Backdoor` | `Backdoor` |
| `Keylogger` | `Trojan-Spy` |
| `Credential stealer` | `Trojan-PSW` |
| `Downloader` | `Trojan-Downloader` |
| `Dropper` | `Trojan-Dropper` |
| `Ransomware` | `Trojan-Ransom` |
| `Banking trojan` | `Trojan-Banker` |
| `Rootkit` | `Rootkit` |
| `Worm` | `Worm` |
| `DDoS` | `Trojan-DDoS` |

Для `Loader` назначение уточняется только при прямом утверждении о самой
программе в описании: `<название> is a downloader` или `... is a dropper`.
Так GuLoader получает `Trojan-Downloader`. Упоминания чужих семейств и
доставляемых нагрузок не добавляют ему классы.

Маппинг намеренно неполный: например, `Info stealer` не уточняет, крадёт ли
программа пароли, сообщения или другие данные. `Botnet`, `Miner`, `Loader`
без уточнения и прочие типы без однозначного соответствия пропускаются.
Классы из нескольких карточек одной группы объединяются без повторов.
Все итоговые названия проверяются по справочнику из задания.
При нехватке данных `malware_class` остаётся пустым; классы по названию
семейства или антивирусным детектам не угадываются.

`av_detects` содержит уникальные непустые строки `result` из
`last_analysis_results` VirusTotal для категорий `malicious` и `suspicious`.
Строки сортируются. `undetected`, ошибки, тайм-ауты и неподдерживаемые типы
не считаются детектами. Пустой список при имеющемся отчёте означает отсутствие
таких строк, а отсутствующий отчёт останавливает сборку.

## Логика threat_level

Оценка отражает потенциальные последствия известных возможностей ВПО.
Это заданная для проекта политика, а не вероятность заражения или ущерба.
Уровень вычисляется только по `malware_class`, как требует задание.
Для нескольких классов выбирается максимальный уровень.

| Уровень | Классы | Обоснование |
| --- | --- | --- |
| `LOW` | `Spam`, `Adware`, `WebToolbar`, `Hoax`, `Trojan-Clicker` | Навязчивая реклама, нежелательные сообщения и манипуляции трафиком; сами эти классы не устанавливают наличие кражи данных, скрытого управления или самораспространения |
| `HIGH` | `Exploit`, `Trojan-DDoS`, `Trojan-Ransom`, `Trojan-Spy`, `Trojan-IM`, `Trojan-GameThief`, `Trojan-PSW`, `Trojan-Banker`, `Backdoor`, `Rootkit`, `Bootkit`, `Virus`, `Worm`, `IRC-Worm`, `IM-Worm`, `P2P-Worm`, `Email-Worm`, `Net-Worm` | Эксплуатация уязвимостей, нарушение доступности, шифрование, кража данных, скрытое управление, сокрытие присутствия или самостоятельное распространение |
| `MEDIUM` | Все остальные классы из справочника задания | Возможность загрузить или установить нагрузку, злоупотребить инструментом либо нанести иной вред; класс сам по себе не устанавливает более тяжёлые возможности из группы `HIGH` |
| `UNKNOWN` | Пустой `malware_class` | Источников недостаточно для оценки; это не означает, что файл безопасен |

Примеры: `Trojan-Downloader` даёт `MEDIUM`, сочетание `Trojan-Downloader`
и `Trojan-PSW` даёт `HIGH`. Число классов и число детектов VT не повышают
уровень автоматически. Результаты VT не меняют уровень, если класс неизвестен.

В задании задан минимальный набор `LOW`, `MEDIUM`, `HIGH`; дополнительный
`UNKNOWN` отделяет недостаток данных от низкой опасности. Все три основных
уровня реализованы, но их наличие в конкретной выборке зависит от её классов.

## Кэш и импорт

- `cache/malwarebazaar.json`: исходный ответ MalwareBazaar.
- `cache/etda.json`: исходный справочник ETDA.
- `cache/virustotal/<sha256>.json`: успешный отчёт VT.
- `cache/virustotal_summary.json`: состояние последнего сбора VT.

В сводке есть счётчики `cached`, `downloaded`, `not_found`, `not_ready`,
`error` и `pending`. `all_reports_available` равно `true` только для полной
сотни отчётов. Хэши без отчёта проверяются заново при следующем запуске.

VT запрашивается последовательно с интервалом минимум 16 секунд.
Сбор 100 новых отчётов занимает около 27 минут плюс время ответов API.
При временных сбоях выполняется до трёх попыток с паузами не менее 60 секунд.
Учитывается `Retry-After`; при требуемой паузе свыше 300 секунд сбор останавливается.
Неверный ключ, повторное ограничение квоты или три последовательные ошибки
останавливают сбор с сохранением прогресса. Ctrl+C также сохраняет прогресс.
Следует запускать одну копию программы с данным ключом.

MalwareBazaar использует POST, ETDA и VirusTotal используют GET.
`--refresh` обновляет данные выбранного режима и не запускает повторный
анализ файлов в VirusTotal. Режим `vt` сам фид не пересобирает.

`cache/` включён в репозиторий как зафиксированный набор исходных ответов:
100 отчётов VirusTotal, ответы MalwareBazaar и ETDA, сводка сбора.
Вместе с `output/feed.jsonl` он позволяет проверить результат и воспроизвести
сборку без запросов к API. Обновление источников меняет этот набор;
для сохранённого результата используется режим `build`.

Из Git исключены `.env`, виртуальное окружение, файлы Python `__pycache__`.

Источники: [MalwareBazaar API](https://bazaar.abuse.ch/api/),
[ETDA Tools](https://apt.etda.or.th/cgi-bin/getmisp.cgi?o=t),
[VirusTotal File API](https://docs.virustotal.com/reference/file-info),
приложенный к заданию файл «Описание классов ВПО.docx».

## Тесты

В проекте 20 тестов на стандартном `unittest`. Запуск из корня проекта:

```bash
python -m unittest discover -s tests -v
```

| Файл | Тестов | Основные проверки |
| --- | ---: | --- |
| `tests/test_feed.py` | 12 | Названия и псевдонимы ETDA, отсутствие и неоднозначность семейства, `same-as`, уточнение GuLoader, фильтрация AV-детектов, соответствие хэшей, уровни опасности, структура JSONL и сохранение предыдущего фида при ошибке |
| `tests/test_importers.py` | 7 | Запрос 100 образцов MalwareBazaar, лимит запросов VT, ошибки доступа, `Retry-After`, остановка при повторном HTTP 429, использование кэша и продолжение после прерывания |
| `tests/test_main.py` | 1 | Полная сборка 100 записей из искусственного кэша без ключей, повторяемость результата и сохранность исходных данных |

Дополнительные зависимости, ключи и доступ к сети не нужны. Ответы API и
паузы заменены моками, файлы создаются во временных папках. Рабочий `cache/`
и итоговый `output/feed.jsonl` при запуске тестов не изменяются.
